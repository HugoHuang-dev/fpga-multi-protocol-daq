# v8: On-board PCF8563 real-time clock

U6 on the Davinci V2.1 schematic is a PCF8563 RTC. Its SDA/SCL share `IIC1_SDA/IIC1_SCL` with the U5 24C64 EEPROM, mapped to FPGA pins T4/R6. The RTC's seven-bit I²C address is `0x51` (bus write byte `A2`, read byte `A3`). The board also has a CR1220 backup-battery holder.

In the project generated by `create_rtc_project.tcl`, v8 retains v7's four-channel XADC, sample FIFO, `TYPE=91` batch frames, CRC-16, UART, and EEPROM commands. PCF8563 registers `02`–`08`, from seconds through year, are read or written consecutively within one I²C transaction to obtain a coherent calendar value. The RTC and EEPROM controllers take turns on the shared I²C bus.

## Commands and time data

The frame remains `A5 5A | TYPE | SEQ | LEN | PAYLOAD | CRC_LO | CRC_HI` with CRC-16/MODBUS.

| Purpose | Request | Response |
| --- | --- | --- |
| Read time | `TYPE=07, LEN=0` | `TYPE=87, LEN=8` |
| Set time | `TYPE=08, LEN=7` | On success, `TYPE=88, LEN=1, PAYLOAD=00` |
| Stream time marker | Generated automatically | `TYPE=92, LEN=8`, approximately once per second |

The seven `08` request bytes are second, minute, hour, day, weekday, month, and year in BCD. Year represents 2000–2099; Monday is weekday 0. The eight-byte `87` and `92` payload is `NEXT_BATCH_SEQ | RTC_REG_02 ... RTC_REG_08`. The seconds register's top **VL** bit signals low voltage; if set, write the time and read it back. In a `92` marker, `NEXT_BATCH_SEQ` identifies the next sample batch after the RTC read completed, creating a roughly one-second time anchor. An I²C NACK returns `E3 01`; a busy bus returns `E4 01`. `TYPE=91` sample frames retain the v7 layout.

## Board procedure

Generate the v8 project with `create_rtc_project.tcl`, build it with `build_rtc_bitstream.tcl`, and program the resulting bitstream. Use 115200, 8N1, Hex on the serial port. First send `A5 5A 07 00 00 C0 01` and look for an `A5 5A 87 ...` reply. If the time is incorrect or VL=1, generate a set-time frame from the current local time:

```powershell
$rtcNow = Get-Date -Format 'yyyy-MM-ddTHH:mm:ss'
py -3 .\host\protocol_crc16.py rtc-set --time $rtcNow
```

Send the complete Hex output through the serial utility, wait for the `88` acknowledgment, and read the time again. Use `py -3 .\host\protocol_crc16.py decode "complete received Hex frame"` to check CRC, time, and VL. Check set/read within a few seconds; the board calendar stores local time without a time-zone field.

Then close the serial utility and run a short automated capture:

```powershell
py -3 .\host\stream_monitor.py --port COM10 --duration 5 --raw capture_v8.bin --summary capture_v8.json
```

`COM10` was the September short-test serial port. The summary contains four-channel statistics and `rtc_time_markers`. In this capture, the markers advanced continuously, `voltage_low=false`, and CRC, sequence-gap, and drop statistics were zero. See the [v8 board record](VALIDATION_V8_2026-09-17.md).

## Validation

Simulation covered the seven-byte RTC I²C read/write, UART time set/read, periodic `92` markers, EEPROM functions, and four-channel frames. Vivado 2018.3 generated the bitstream with 13.422 ns WNS and zero TNS against the 50 MHz constraint. The SHA-256 of `releases/xadc_rtc_v8.bit` matches the project bitstream: `8EEA90DBD2F2671A4A230DFE15A3BD86CC0A2817789AB6D337C4FEF29F5C4708`. The September [five-second board capture](VALIDATION_V8_2026-09-17.md) and [two-hour run](VALIDATION_FINAL_2026-09-18.md) record functional responses and long-run frame statistics. Register definitions follow the board documentation's NXP `PCF8563.pdf` (pages 7 and 13–14).
